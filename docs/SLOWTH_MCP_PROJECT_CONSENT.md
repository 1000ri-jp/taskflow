# Slowth MCP の複数プロジェクト読み取り同意

接続本人が現在閲覧できるプロジェクトから、読み取り対象の固定リストを明示同意する実装です。書き込み・AI作業・イベントは別のプロジェクト単位の同意が必要です。既存の接続は引き続き `SlBpu8BPYgIARk4DoYOV` の pilot だけを許可し、対象追加には本人のOAuth再同意が必要です。

## 設定だけでは対応できない理由

調査した main は `0766176e49da29690c9c34f16875505794f49340`（PDFサムネイル PR #116 を含む）です。既存の同意APIはプロジェクト一覧をpilotに絞り、単一の `projectId` を保存します。OAuth認証・refresh、イベント生成・配信にもpilot制約があります。既存接続の設定変更だけでは複数プロジェクトを読み取れません。PATの全プロジェクト指定は別の認可方式なので、OAuth同意を迂回する代替にはしません。

PDF作業のローカル配備結果記録では、本番 `build-2026-10-15-pdf-003` は当時のliveソースにPDF変更を加えた構成です。main全体と同一とは扱いません。その保存済み本番候補と、今回変更する既存MCPファイルを比較したところ、`coordinatorTransport.ts` はmainの方に元grant・Firebase失効検証が追加されていました。他の比較対象10ファイルはmainと一致しました。今回の変更はmainの検証を保持します。公開候補は最新liveソースとの差分を改めて確認し、main全体で上書きしないでください。

## 同意モデル

`SLOWTH_MCP_MULTI_PROJECT_READ` は未指定・`false` が既定です。有効化には既存のproduction/task access設定も必要です。公開候補の `apphosting.yaml` は、この機能を明示的に有効にします。コードや設定の配備だけで既存のgrantは拡張されません。

新しいproduction接続で `tasks:read` を要求した場合、本人の現在のプロジェクト一覧とメンバーロールを照合して選択画面を表示します。閲覧専用メンバーも読み取り対象を選べます。選択欄は初期状態ではすべて未選択です。「現在閲覧できる全件」は、その画面に表示した読み取り対象だけを選びます。

| grant項目 | 意味・制約 |
| --- | --- |
| `consentVersion: 2` | 新しい形式の明示同意 |
| `projectIds` | 同意した読み取り対象の固定リスト |
| `writeProjectIds` | 読み取り対象のうち、別途書き込みを許可した対象 |
| `aiProjectIds` | 書き込み対象のうち、別途AI計画・作業委任を許可した対象 |
| `eventProjectIds` | 読み取り対象のうち、別途イベントを許可した対象。現在はpilotのみ |
| `includeFutureProjects: false` | 将来のプロジェクトを自動で含めない。`true` は拒否 |
| `taskScopes` | OAuth要求範囲。プロジェクト別の上記リストと両方を満たす必要がある |

同意は最大30日です。1回の同意は最大500件で、超過時に暗黙の切り捨てや全件wildcardは使用しません。選択対象の名前・IDと、読み取り／書き込み／AI作業／通知の最終一覧を同意画面に表示します。

既存の単一 `projectId` grant は元の1件だけに互換対応します。v2の配列を後付けした旧形式や、不明な形式、重複ID、対象外の書き込み、未同意プロジェクトのAI・イベント指定は拒否します。既存grantの拡張・移行更新は行いません。対象追加時には接続を開始し直して新しいgrantへの本人同意が必要です。

## 読み取りとセキュリティ境界

共通ツールに以下のresourceを追加します。新しい専用ツールや横断データベースは作りません。

```json
{"resource":"projects","limit":20}
```

同意済み対象のうち現在も閲覧できるプロジェクトを返します。`next_cursor` があれば続けて取得してください。結果にはプロジェクト名、ロールと実効的な `read` / `write` / `ai_work` / `events` 許可が含まれます。将来の追加対象や未同意プロジェクトは返しません。

```json
{"resource":"project_status","project_id":"同意済みID"}
```

既存の共有サービスから件数とリスト別進捗を返します。タスク本体・コメント・確認・チェックリスト・子タスク・添付・履歴は、既存resourceに同じ `project_id` を付けて取得します。複数対象の接続では、対象を省略して先頭プロジェクトを暗黙選択することを禁止します。

各データ操作では、同意範囲と現在のメンバー配列・ロール文書を照合します。viewerは書き込めません。アーカイブ済み、権限を失った対象は拒否します。v2の読み取りはAI作業設定とは独立し、書き込みは既存のAI利用範囲の制約も保持します。書き込みはトランザクション内でもgrantとメンバー権限を確認します。タスク・子リソース・添付内容の取得後にも対象の権限を再確認します。保存した添付を使って別プロジェクトのStorageパスを取得することは拒否します。

トークン検証で全プロジェクトの実データやメンバー情報を毎回走査しません。OAuthは同意スナップショットを検証し、対象へのアクセス時に現在の権限を照合します。refreshは同意範囲内に現在アクセス可能な対象が残っていることを確認し、新しい対象を追加しません。1件の権限剥奪で他の同意済み対象まで無効にする設計にはしません。

AI計画・ポリシー変更・作業委任は `aiProjectIds` の明示同意が必要です。保存したワーカー委任には、その仕事の1プロジェクトだけを渡し、イベント対象も空にします。実行には既存のプロジェクト別調整設定・能力ポリシー・人間確認・現在のAI利用設定も必要です。この実装だけで他のプロジェクトのAIワーカーは起動しません。

## イベントとの分離

`events:read` は現在のOAuth要求契約に必要ですが、v2ではそれだけで通知や購読を許可しません。フィード取得、ACK、購読は `eventProjectIds` と現在の閲覧権限で検証します。読み取りの全件選択はイベントを選びません。

イベント生成のFirestoreパスと配信設定はpilot固定を維持します。ワーカー側にも `SLOWTH_MCP_MULTI_PROJECT_READ=false` を既定とする独立ゲートを追加し、v2通知は明示的な有効化前には処理しません。既存の旧形式pilot通知は、元の設定のまま扱います。購読の検証コールバック後とフィード取得後には同じBearerを再検証し、同じ本人・grant・modeの現在のイベント同意、メンバー権限と期限を確認します。ACKはBearerの再検証に加え、書き込みトランザクション内で元grant・同意・プロジェクト・ロール文書・本人プロフィールを読み、失効や権限剥奪を拒否します。配信直前にも現在のgrant・メンバー・購読・journalのプロジェクト一致を確認します。既存購読や定期通知の更新は行っていません。

## 今回の検証と公開までの残り

テストは架空の認証・メモリ内Firestore・架空添付を使用します。UIのブラウザテストは実際の同意コンポーネントと共通CSSをビルドし、認証とHTTPのみを架空に置き換えます。実OAuth同意、実データ、実通知購読を必要としません。

```sh
npm run worker:test
npx playwright test --config playwright.mcp-consent.config.ts
npm run build
```

公開前の独立レビューと指摘修正は完了しています。Git保存・PR・マージと本番配備は、2026-10-15の続行指示に基づき進めます。必須CIを通し、最新main/liveの差分を確認して、本番ソースに今回の対象だけを加えた候補を作成します。新しいIAM権限、クラウド資源、依存パッケージ、Firestore索引は追加していません。

アプリの `SLOWTH_MCP_MULTI_PROJECT_READ=true` が配備された後、本人が新しい接続から対象を確認して同意します。まず読み取りだけならOAuth要求は `events:read tasks:read openid offline_access`、同意対象は `projectIds` のみとし、書き込み・AI・イベントは空のままにします。書き込みが必要なら `tasks:write` の追加と、該当プロジェクトの明示選択が必要です。v2でpilot通知を引き続き許可する場合のみ、Functions側ゲートの有効化と本人のイベント選択を別途行います。通知登録や既存接続の解除も別の指示が必要です。

本人が新しい接続で対象を確認して再同意するまでは、既存接続の読み取り範囲は増えません。公開時の承認審査が失敗した場合はそのまま停止し、エラーを記録してください。今回のローカル検証は過去の配備承認の代替ではありません。
