# コメント通知と共有の確認依頼

## 使い方

タスク詳細のコメント欄で指定し、最後に投稿する。

- 「メンバーに通知」：選択したプロジェクトメンバーに、投稿と同時にアプリ内通知。未選択なら通常コメントから通知は送らない。
- 「確認依頼」：依頼内容、担当者（複数可）、確認期限（任意）。依頼先には「メンバーに通知」の選択にかかわらず通知する。
- 両方で同じ人を選んだ場合は、確認依頼の通知1件にまとめる。
- 確認依頼は今開いているタスクの共有子タスク1件。全担当者の「マイタスク」と、未読時の「今日のブリーフ／返信待ち・重要」に表示する。担当者本人が表示できるプロジェクト内で作成する。
- 複数担当でも完了状態は共通。個人別の完了チェックではない。親タスクの完了とは連動しない。
- 親の詳細に子タスク一覧、子の詳細に親・元コメントへのリンクを表示。元コメントはURLの `comment` パラメータでスクロール・強調する。
- 計画リストでは親の下に子を表示。カンバンとテーブルでも子タスク・親の名前がわかる。

これはブラウザだけの試作保存ではなく、投稿時に既存Firebaseへ共有保存する。既存のチェックリスト項目の担当者は引き続きブラウザ限定であり、今回の共有子タスクへ自動移行しない。

## データ構造（追加のみ）

| 保存先 | 追加・利用する項目 |
| --- | --- |
| `projects/{projectId}/tasks/{childId}` | `parentTaskId`, `sourceCommentId`, `taskKind: review_request` を追加。担当者、期限、完了・アーカイブは既存Task項目を使う |
| 親タスクの `comments/{commentId}` | `reviewTaskId` を追加。本文、添付、投稿者、通知先を保存 |
| `notifications/{commentId}:{userId}` | 確認依頼に `review_requested` を追加。通常コメントは `comment_added`。依頼は子タスク、コメントは元コメントにリンク |
| `projects/{projectId}/activityLogs/comment-{commentId}` | 既存活動ログに投稿の受領記録を保存。`sourceTaskId`, `commentId`, `reviewTaskId` を追加 |

コレクションの新設・既存フィールドの削除はしない。FireStoreルールも変更・デプロイしない。既存の認証・プロジェクト権限で処理する。依頼先が最新の `project.memberIds` に含まれることを投稿時にも検証する。

## 失敗・再試行

- コメント、子タスク、通知、活動ログを1トランザクションで保存し、一部だけ登録された状態を防ぐ。
- 投稿前にIDと入力をタブの `sessionStorage` へ退避。結果不明の場合は編集を止め、同じIDで再試行する。
- 受領済みなら追記も上書きもしない。通知の既読、子タスクの完了、コメント削除を再試行が巻き戻さない。
- 未登録と確定できた対象・メンバーのエラーでは入力の修正を再開できる。
- 添付はDB保存前に既存Storageへアップロードする。アップロード失敗時はDBへ投稿しない。DB失敗後の添付や、利用者が取り外した添付の自動削除は行わない（孤立ファイルの掃除は別途）。
- 通信結果不明時は同じタブで再試行すること。タブを閉じると退避が失われるため、再投稿前に元コメント一覧を確認する。
- 親や元コメントの削除・アーカイブで子を自動削除しない。親が通常のボードで表示されない状態では元リンクも開けないことがある。
