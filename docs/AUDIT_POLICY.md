# 依存監査と期限付き例外

`taskflow-ci / audit` は引き続きmainへの必須チェックです。`npm run audit` はoptionalを除く全依存のnpm監査と、実行時依存のnpm監査を取得し、`security/audit-exceptions.json`の限定条件を検証します。ネットワーク・実行・JSON形式の異常は失敗として扱います。`npm run audit:raw`と依存健全性レポートは未加工のnpm結果を保持します。

## 2026年10月9日に承認した例外

- 対象は[GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)の1件のみ。highのままで、修正版や撤回は確認されていません。
- 有効期限は**2026年10月16日まで（日本時間）**。10月17日00:00 JST以降、この問題が残る場合は監査が失敗します。自動延長はしません。
- 承認範囲は、開発用の`eslint-config-next@16.3.8 → @next/eslint-plugin-next@16.3.8 → fast-glob@3.3.1 → micromatch@4.0.8 → braces@3.0.3`だけです。npmが報告する5つの影響項目は、この1件の伝播です。
- 実行時依存の監査は0件であることを毎回確認します。別の脆弱性、実行時の影響、追加のパッケージ経路は受け入れません。
- パッケージのバージョン・integrity・開発用フラグ・依存経路、現在のlint設定とlintコマンドを固定して照合します。条件が変われば例外は無効になります。
- アプリ・通知処理・Functions・ワーカーとルートの実行設定も検査します。開発依存でもアプリからimportすれば本番に含まれ得るため、対象パッケージへの実行時参照や未レビューの計算されたモジュール読込を拒否します。既存のワーカー読込処理だけは、レビュー済みファイルのハッシュで固定します。

この判断の根拠は、現行のNext lintプラグインが`settings.next.rootDir`にglobを指定した場合だけ`fast-glob`を呼び、現在の有効設定にはその指定がないことです。実行時依存の監査が0件という事実と、現在の設定で問題の処理へ到達しないという評価を組み合わせています。任意の将来設定でも安全という意味ではありません。

実行時参照の検査はソースの静的検査であり、本番bundle全体の到達可能性を証明するものではありません。新しいソースの通常のPRレビューも引き続き必要です。

リポジトリ所有者は2026年10月9日、この条件での期限付きリスク受容と、他の必須チェックが成功した後のPR #106のマージを承認しました。例外の期限・対象・条件を広げる場合は別の判断として記録します。

## 検証と解消

```sh
npm run audit:policy:test
npm run audit
npm run audit:raw
```

方針テストは架空の監査結果で、期限境界、別の勧告、実行時の影響、依存・設定の変更、欠落・不正な応答などを確認します。通常のlint・test・build・e2eチェックも維持します。

上流の正式修正または撤回により全依存の監査が問題なしになれば、期限経過後も監査は成功します。修正版への更新を別途検証し、この例外を削除してください。問題が残ったまま期限を迎えた場合は、依存監査が再びマージを止めます。これは配備の停止や稼働ワーカーの停止を自動的に行う仕組みではありません。
