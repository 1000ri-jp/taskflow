# プロジェクトのタスク表示（ローカル試作）

ボード上部の切り替えで、同じ既存データを4種類の表示にできます。既存のガントチャートは上部タブから引き続き利用できます。

| 表示 | 用途 | 表示するデータ |
| --- | --- | --- |
| カンバン | 列を横並びで確認 | 既存のカード・列。操作は従来どおり |
| 計画リスト | 分類と作業の階層を確認 | 現在の列 → タスク → 共有の確認依頼・子タスク／チェックリスト。チェックリストは左矢印で展開 |
| テーブル | 担当・日付・状態を一覧比較 | タスク、分類、完了状態、担当者、開始日、期限、優先度。見出しで昇降順切替 |
| カレンダー | 日付に沿って確認 | 月／週、実際の開始日・期限。未設定タスクは下部へ分離 |

## 共通動作

- タスク名クリックで従来の詳細モーダルを開く。
- 検索・期限・ラベル・完了表示の条件は、同じボードページ内でビューを切り替えても保持する。
- アーカイブ済みタスクは新しいビューに表示しない。
- カテゴリ名から進捗を推定しない。「東京ゲームダンジョン」など現在の列名は分類として表示し、完了状態と別に扱う。
- チェックリストは展開時に読み込む。取得失敗は「なし」ではなくエラー表示＋再試行。詳細を閉じた際に再取得する。
- チェックリスト担当者は既存のブラウザ限定設定を表示する。共有担当者フィールドの追加・移行はしない。
- コメントから登録した共有の確認依頼は親の下に表示する。親が表示条件から外れても子は消さない。確認依頼の保存・通知は [SHARED_COMMENT_REVIEW_REQUESTS.md](./SHARED_COMMENT_REVIEW_REQUESTS.md) を参照。
- テーブルのソートは表示専用。共有タスクの `order` を変更しない。
- カレンダーは開催日を推定しない。開始・期限が同日の場合は1件にまとめ、異なる場合はそれぞれ表示。期間バーは既存ガントで確認する。

## 主表示とURL

「この表示を主表示にする」で、ログインユーザー×プロジェクトごとにブラウザへ保存する。

- 保存キー：`taskflow.projectTaskView.v1`
- スコープ：`JSON.stringify([viewerId, projectId])`
- 値：`board | outline | table | calendar`
- 明示的なURL `?view=...` が最優先。未指定なら保存値、初期値はカンバン。
- 同じユーザー・プロジェクトの別タブに保存変更を同期。
- 保存不能時は警告を表示し、その画面内だけの設定として継続。
- 別ブラウザ・別端末との同期はしない。既存 `/` と `/my-dashboard` の構成は変更しない。

## 変更しないもの

プロジェクト・列・タスク・チェックリストの再編成、新規受注/KPI/イベント専用フィールド、共有の主表示設定は追加していない。表示切替・ソート・主表示保存ではFirestoreへ書き込まない。詳細画面内の既存編集操作は従来の保存処理を使う。
