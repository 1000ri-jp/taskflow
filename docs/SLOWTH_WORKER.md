# Slowthローカル実行ワーカー

`tools/slowth-worker/` は、Slowthの計画でAIに割り当てられた作業を、登録済み資料のコピーで実行する独立したNode.jsサイドカーです。Next.jsアプリの実行やFirebaseの配備だけでは起動しません。公開ソースには実アカウント、接続トークン、作業委任、稼働中ワーカーの設定・状態・成果を含めません。

ここに記載する安全性の修正は統合ブランチ内のサイドカーへの変更です。既存の稼働中ワーカーは変更・再起動していません。既存運用へ適用するには、別途レビューとロールアウトが必要です。

Dotはタスク・コメント・確認回答を読み、目的に応じて人間とAIの仕事を判断します。ワーカーは現在の有効な計画から実行可能なAI作業を一件ずつ選び、成果物・検証結果・人間への確認依頼をSlowthへ返します。ワーカーの正常終了は人間の受け入れや親タスクの完了を意味しません。

## 実行条件と責任範囲

- Node.js 22 LTS、インストール済みのリポジトリ依存関係、Python 3.11以降の`tomllib`、Gitが必要です。`esbuild`は信頼したサーバーソースをNode 22向けにローカルでコンパイルします。
- 実モデル作業には、既存のChatGPTログインを使うCodex CLIが必要です。モデル指定を追加せず、設定済みモデルを使用します。APIキーによる課金経路へ自動的に切り替えません。
- 常駐ホストには、既存のApplication Default Credentialsと、対象プロジェクトへ許可された現在のOAuth作業委任が必要です。ソースを導入しても認証情報や委任を作成しません。
- Firebase、OAuth、プロジェクト方針、資料範囲、担当者の登録は、それぞれレビュー済みの設定で一致させます。ワーカーが勝手に対象プロジェクト・メンバー・能力を追加することはありません。
- Macのスリープ・停止中は作業できません。ハートビート失効により未接続と判断します。この公開サイドカーはログイン時の自動起動やOSサービスを登録しません。

## 公開してよいソースと私有設定

リポジトリルートで、`tools/slowth-worker/config.example.json`を私有の`tools/slowth-worker/config.local.json`へコピーし、すべてのプレースホルダーを承認済み値へ変更します。例のままでは起動できません。別の場所へ置く場合は、相対パスの基準が設定ファイルのディレクトリになることに注意してください。

| 設定 | 意味 |
|---|---|
| `projectId` | 明示的に承認したSlowthプロジェクトID。一つの設定で一プロジェクトを実行 |
| `workerId` | 現在のホストを識別する安定したID |
| `stateDirectory` | 私有の実行状態、原資料コピー、成果、ログ、操作再送記録の保存先 |
| `sources` | 承認済み資料IDからローカルディレクトリへの対応。方針の`scope.sourceIds`との共通範囲のみ使用 |
| `serverSourceRoot` | 常駐ホストがコンパイルする、レビュー済みSlowthサーバーソースの場所 |
| `firebase.projectId` / `storageBucket` | 常駐ホスト用の明示的なFirebase接続先。認証情報を格納する欄ではない |
| `mcpEndpoint` | 接続型の単発実行で使うHTTPS MCP URL。資格情報・クエリ・フラグメントは禁止 |
| `codexCommand` / `pythonCommand` | 実行バイナリ。省略時は`codex` / `python3` |

`SLOWTH_WORKER_CONFIG`で使用する設定ファイルを明示します。未設定、未完成の設定、未知の欄、資料を内包する状態ディレクトリは起動前に拒否します。`config.local.json`と`state/`はGitへ保存しません。別名や別の場所を使う場合も、私有設定・状態・トークン・ADCを公開対象から除外してください。

資料の全体取り込みは設定ファイルと実行状態を明示的に除外し、`.env*`、秘密鍵、認証情報名のJSON、Git・ビルド成果・依存ディレクトリなども除外します。認証情報は資料ディレクトリの外へ保存してください。除外規則は機密情報の自動検出を保証するものではありません。既存の`node_modules`は読み取り用リンクとして利用し、ワーカー内でインストールしません。

## 資格情報を使わない検証

```sh
npm run worker:check
npm run worker:test
```

`worker:check`はJavaScriptの構文と公開JSONのみを確認します。`worker:test`は架空プロジェクト・架空ユーザー・一時ファイル・偽の実行バイナリ・インメモリFirestoreを使います。実Codexモデル、稼働中ワーカー、Firebase、既存の実タスクへ接続しません。テスト実行は選択したNodeバイナリを子プロセスにも使います。Node 26での結果だけでNode 22互換性を判断しないでください。

明示した私有設定を使ったコンパイル確認は次の通りです。このコマンドはローカル状態ディレクトリへ生成コードを書きますが、ADC初期化、ハートビート、実作業を開始しません。

```sh
SLOWTH_WORKER_CONFIG=tools/slowth-worker/config.local.json npm run worker:verify
```

## 常駐ホストの設定と開始

サーバーで承認済みの認証ガードを、ホストの私有実行環境にも設定します。必要な変数は`SLOWTH_MCP_OAUTH_ENABLED`、`SLOWTH_MCP_OAUTH_ORIGIN`、`SLOWTH_MCP_OAUTH_ALLOWED_UID`、`SLOWTH_MCP_OAUTH_CLIENT_ID`、`SLOWTH_MCP_OAUTH_REDIRECT_URI`、`SLOWTH_MCP_EVENTS_PRODUCTION`、`SLOWTH_MCP_EVENTS_PROJECT_ID`、`SLOWTH_MCP_TASK_ACCESS`、`SLOWTH_MCP_COORDINATION_PROJECT_IDS`です。現在のサーバーの対象範囲に一致するレビュー済み値を使用します。`SLOWTH_MCP_COORDINATION_PROJECT_IDS`の設定だけではOAuthの対象範囲は拡張しません。

これらは現在のOAuth許可・Google本人情報の再検証に必要です。ガードが不足している、対象UIDが変わった、元のOAuth許可が取り消された、Googleアカウントが無効になった場合は停止します。署名鍵、Cookie鍵、OAuth保存暗号鍵はこのメタデータ検証に不要であり、ワーカーへ渡しません。認証情報をworker設定JSONへ追加すると拒否します。

承認済みのFirebase方針・AI担当・能力・資料範囲・有効な委任がある状態で、前景プロセスとして開始します。次のコマンドはハートビートを登録し、実際のモデル利用・成果保存を行える運用コマンドです。

```sh
SLOWTH_WORKER_CONFIG=tools/slowth-worker/config.local.json npm run worker:run
```

`worker:run`は`--allow-account-usage`を含みます。実モデル利用を許可せずホストの挙動を確認する場合は、`node tools/slowth-worker/host.mjs --once`を明示設定の下で使います。ただし`--once`もハートビートを書き、作業があればリース取得・実行準備を進める運用操作です。資格情報を使わない確認には前述のfixtureテストを使ってください。

Ctrl-CまたはSIGTERMで停止し、現在のモデルプロセスの停止とハートビート解除を行います。別のホストが所有するリースを引き継ぎません。`stateDirectory/host-status.json`の`scan_status`は現在の巡回状況、`status`は最近の作業結果を表します。状態ファイルには私有情報が含まれるため公開しません。

## 接続済みMCPから一件を実行する場合

`run-connected.mjs`は既存のMCPトークンを私有ファイルから各リクエスト時に読みます。`SLOWTH_MCP_TOKEN_FILE`で場所を指定してください。トークンをJSON設定・コマンド引数・リポジトリへ書きません。

私有の作業指定JSONは`parentTaskId`、`planId`、`workId`と、必要なら`reviewerIds`を含めます。`payload`を省略すると、ブリッジが現在のサーバー計画の`work.execution`から資料・ファイル・ハッシュ・依頼文・確認方法を導出します。互換用に`payload`を含める場合は、現在の実行内容と完全一致する必要があります。資料変更、依頼文変更、別の過去ジョブ指定などは実行前に拒否します。前提タスクの現在値や人間の修正回答は、ブリッジ自身の認証済み読み取りから追加します。

```sh
node tools/slowth-worker/run-connected.mjs private-work-spec.json --allow-account-usage
```

このコマンドにも明示的な`SLOWTH_WORKER_CONFIG`と`SLOWTH_MCP_TOKEN_FILE`が必要です。エンドポイントとOAuthの対象範囲は同じ承認済み接続にします。単発実行でも、対象ホスト・能力・資料範囲の現在の登録が必要です。

接続済みブリッジが対応する能力は`local.codex_workspace`です。`local.evidence_package`、`local.draft_artifact`、`local.isolated_patch`は、提供済み内容を検証・保存するオフライン補助アダプターとして保持しています。共通のサーバー実行契約を持たないため、接続済みの自動実行には使用しません。`worker.mjs registry`は設定済み資料IDとこのアダプター一覧を返すだけで、サーバーへの登録や検証済み能力の宣言を行いません。

## 検証、成果、再開の扱い

ワーカー自身の後処理検証は`json_validate`と`node_syntax`を扱います。生成したテストコードを特権ホストで実行する`node_test`は、OSによる強制的な実行隔離を導入するまで`EXECUTABLE_CHECK_ISOLATION_REQUIRED`で拒否します。計画の検証指定に含まれていれば、モデル利用前に停止します。振る舞いのテストは隔離されたCodex実行内で行い、観測した結果を返します。構文検証の子プロセスにはNodeのプリロード設定やホスト資格情報を引き継ぎません。

`slowth-source`のCodexネットワークは既存Nextコンパイル用のGoogle Fonts二ドメインに制限し、他の登録資料はオフラインです。設定済み外部MCPとプラグインを無効化し、CLI隔離設定を受理できない場合はモデル利用前に停止します。実装結果はコピー内の変更と差分であり、元の資料への適用、Git操作、配備を行いません。

すべての実行チェックが成功してから成果を返します。失敗したチェックを成功へ書き換えません。実際の非空ファイル、SHA-256、MIME、10 MiB上限を確認し、添付・親コメント・確認依頼・計画結果を保存します。成果が10件を超える場合は親コメントへ分割し、全成果のマニフェストを確認依頼へ付けます。

同じ実行は安定したジョブIDと操作記録で再送します。失敗・既存の成功結果が自ホストの有効リース下に残った場合は、最新の認証済みチェックポイントを通って同じジョブから復旧します。ハートビートや兄弟作業の更新では失敗の待機時間を回避しません。実行入力・修正回答・リビジョンが変われば新しい試行として扱います。

各試行の実行回答は履歴を保持し、バイナリを含む実変更とハッシュを次の修正へ引き継ぎます。原資料や記録が食い違った場合は、書き戻す前に`PRIOR_SOURCE_CONFLICT`で停止し、親タスクへ診断を残して当該作業のリースを解放します。Dotは現在の資料と要望で再判断し、目的が明確なら理由付きの新計画へ未完了作業を再利用します。目的・変更意図が不明な場合は、人間への確認をまとめます。過去の成果、兄弟の進捗、人間確認履歴は保持します。

公開テストは以上の契約を架空環境で確認するものです。新しい機械の資格情報、Codex OS隔離、ネットワーク制限、運用方針、実際の承認済み接続が動くことは、対象環境での別途の運用確認が必要です。
